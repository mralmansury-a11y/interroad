# نظام إدارة موارد المشروع — الجهاز الوطني للتنمية

نظام لإدارة العمالة والمعدات والمواد عبر مواقع/قواطع المشروع، مبني بـ Flask + SQLite.
**الإصدار 2** — نسخة موسّعة بميزات احترافية للاستخدام الفعلي في متابعة المشاريع الميدانية.

## التشغيل محليًا

```bash
pip install -r requirements.txt
python app.py
```

ثم افتح المتصفح على: `http://localhost:5000`

يتم إنشاء قاعدة البيانات تلقائيًا مع بيانات تجريبية عند أول تشغيل (ملف `project_resources.db`).
لإعادة تعيين البيانات التجريبية، احذف هذا الملف وشغّل التطبيق من جديد.

## حسابات الدخول التجريبية

| اسم المستخدم | كلمة المرور  | الصلاحية                                  |
|--------------|--------------|--------------------------------------------|
| `admin`      | `admin123`   | مدير النظام — كل الصلاحيات + إدارة المستخدمين وسجل النشاط |
| `manager`    | `manager123` | مشرف — إضافة/تعديل البيانات، بدون إدارة مستخدمين |
| `viewer`     | `viewer123`  | اطلاع فقط — عرض البيانات والتقارير دون تعديل |

⚠️ **مهم قبل أي استخدام حقيقي:** غيّر كلمات المرور الافتراضية من صفحة "إدارة المستخدمين"، وغيّر
قيمة `app.secret_key` في `app.py` إلى قيمة سرّية عشوائية.

## أهم الإضافات في هذا الإصدار (حلول لمشاكل حقيقية)

### 1) نظام دخول وصلاحيات (Authentication & Roles)
سابقًا كان أي شخص يملك الرابط يستطيع تعديل كل البيانات دون أي رقابة. الآن:
- تسجيل دخول إلزامي لكل الصفحات.
- ثلاث صلاحيات: **مدير النظام** (كل شيء)، **مشرف** (إضافة/تعديل بيانات ميدانية)،
  **اطلاع فقط** (قراءة وتقارير دون تعديل) — مناسب لمسؤولي المتابعة والتدقيق.
- إدارة مستخدمين كاملة (إنشاء/تعطيل) من صفحة مخصّصة للمدير.

### 2) سجل نشاط / تدقيق (Audit Trail)
كل عملية إضافة أو تعديل أو تحويل أو دخول/خروج تُسجَّل تلقائيًا مع اسم المستخدم والتوقيت،
ويمكن مراجعتها وتصفيتها حسب الفئة من صفحة "سجل النشاط" — ميزة أساسية للمساءلة في مشروع حكومي.

### 3) متابعة الميزانية والإنجاز لكل موقع
كل موقع الآن يحمل: نسبة إنجاز فعلي، ميزانية معتمدة، مصروف فعلي، مدير موقع مسؤول، وحالة
(قيد التنفيذ / متوقف / مكتمل). صفحة تفاصيل مستقلة لكل موقع (`/sites/<id>`) تجمع
العمالة والمعدات والمخزون الخاص به في مكان واحد بدل تتبعها يدويًا عبر عدة صفحات.

### 4) لوحة معلومات برسوم بيانية تفاعلية
أُضيفت رسوم بيانية (Chart.js): اتجاه الحضور لآخر 7 أيام، توزيع حالة المعدات، ومقارنة
الميزانية بالمصروف الفعلي لكل موقع — لتسهيل اتخاذ القرار السريع بدل قراءة جداول فقط.

### 5) تصدير تقارير Excel
مشكلة شائعة في مشاريع الجهات الحكومية: الحاجة لإرسال بيانات إلى جهات أخرى بصيغة جاهزة.
أُضيف تصدير مباشر بصيغة Excel (.xlsx) لكل من: المواقع، العمالة، المعدات، أرصدة المواد،
وتقرير الحضور حسب فترة تاريخية مخصّصة، من صفحة "التقارير والتصدير".

### 6) تقرير حضور وأجور
صفحة تقارير جديدة تحسب تلقائيًا لكل عامل: أيام الحضور، الغياب، الإجازات، الساعات
الإضافية، وإجمالي الأجر المستحق خلال فترة محددة — بدل الحساب اليدوي من سجلات متفرقة.

### 7) تتبّع تكلفة الوقود للمعدات
كل معدة تحمل الآن "تكلفة اللتر"، ويُحسب تلقائيًا إجمالي الوقود المستهلك وتكلفته من سجلات
التشغيل، مما يساعد على رصد الهدر ومقارنة كفاءة المعدات.

### 8) قيمة المخزون والتكلفة لكل مادة
كل مادة تحمل تكلفة الوحدة، فتُحسب قيمة المخزون الإجمالية ولكل موقع تلقائيًا — أداة مهمة
لمتابعة رأس المال المجمّد في المخزون الميداني.

### 9) بحث وتصفية في كل الصفحات الرئيسية
قوائم المواقع والعمالة والمعدات والمواد أصبحت قابلة للبحث الفوري (بالاسم/الرمز/الدور)
والتصفية حسب الموقع، بدل التمرير اليدوي في جداول طويلة.

### 10) رفض طلبات التحويل + تحقق من كفاية الرصيد
سابقًا كانت طلبات التحويل تُنفَّذ حتى لو كان الرصيد في الموقع المصدر غير كافٍ (يؤدي لأرقام
سالبة خاطئة). الآن: يوجد زر "رفض" صريح لطلبات التحويل، والتنفيذ يتحقق أولًا أن الرصيد
كافٍ ويمنع التنفيذ مع رسالة تنبيه إن لم يكن كذلك.

### 11) معالجة أخطاء وتحقق من صحة المدخلات
كل نموذج إضافة/تعديل محاط الآن بمعالجة استثناءات (بدل انهيار الصفحة بخطأ 500)، مع رسائل
تنبيه واضحة بالعربية عند تكرار رمز موقع/معدة، أو إدخال قيمة سالبة، أو نقص بيانات.

## هيكل المشروع

```
app.py                 منطق التطبيق ومسارات Flask (مصادقة، صلاحيات، تصدير، تقارير)
database.py            الاتصال بقاعدة البيانات، سجل التدقيق، وتعبئة بيانات تجريبية
schema.sql              مخطط قاعدة البيانات (يشمل المستخدمين وسجل النشاط)
requirements.txt        Flask + openpyxl (لتصدير Excel) + Werkzeug
templates/               قوالب Jinja2
  base.html              القالب الأساسي (شريط جانبي، شريط المستخدم، صلاحيات)
  login.html             صفحة تسجيل الدخول
  dashboard.html         لوحة المعلومات مع الرسوم البيانية
  sites.html / site_detail.html   المواقع والقواطع + صفحة تفاصيل الموقع
  workers.html           العمالة والحضور (بحث + تصفية)
  equipment.html         الأسطول والمعدات (تتبع الوقود)
  materials.html         المواد والمخزون (تحويلات + قيمة المخزون)
  reports.html           التقارير والتصدير + تقرير الأجور
  users.html             إدارة المستخدمين (للمدير)
  activity_log.html      سجل النشاط (للمدير)
static/style.css         التصميم والاستجابة (هوية الجهاز + إضافات الإصدار 2)
static/logo.png          شعار الجهاز الوطني للتنمية
static/favicon.png       أيقونة التبويب
```

## ملاحظات للنشر الفعلي (Production)

هذا النظام لا يزال نموذجًا أوليًا (PoC) موسّعًا؛ قبل أي استخدام إنتاجي حقيقي يُنصح بـ:
- استبدال `app.secret_key` بقيمة سرّية من متغيرات البيئة.
- تشغيل التطبيق خلف خادم WSGI حقيقي (gunicorn/uwsgi) بدل خادم التطوير المدمج.
- الانتقال من SQLite إلى قاعدة بيانات مؤسسية (PostgreSQL مثلًا) عند تعدد المستخدمين المتزامنين.
- تفعيل HTTPS وقفل ملفات تعريف الارتباط (`SESSION_COOKIE_SECURE`).
- نسخ احتياطي دوري لملف `project_resources.db`.
